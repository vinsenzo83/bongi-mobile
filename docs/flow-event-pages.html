🎁 이벤트 페이지 개발 (12)

공용 이벤트 시스템 — 봉이 플랫폼 오픈 시 N개 이벤트를 1 인프라로 재사용. 슬러그(slug) 1줄 등록으로 새 LP·신청자 관리·쿠폰 발급·알림톡·콜DB 적재 자동.

🎯 1. 비전 — 왜 공용 시스템인가

이벤트는 회사가 성장하는 한 끊임없이 열린다. 매번 새 LP를 디자인·개발하지 않고 슬러그 1줄 + 어드민 입력으로 즉시 신규 이벤트가 가동되어야 한다.

❌ 이벤트마다 개별 개발
매번 LP 디자인·HTML·DB 테이블·어드민 페이지 신규. 개발 2주, 비용 큼, 운영 분산
✅ 공용 시스템 1회 구축
템플릿 + 어드민 + 외부 API 추상화. 신규 이벤트는 어드민에서 입력 → 즉시 가동. 운영 일원화·통계 통합
첫 이벤트 사례: 봉이모바일×Tredit "메가커피 5,000잔 쿠폰" — 중고 보상 시세조회 미끼 + 메가커피 쿠폰 (선착순 5,000명). 이 패턴을 공용 시스템으로 일반화.

🗄️ 2. 도메인 모델 (DB 스키마)

이벤트는 마스터(템플릿) + 신청자(인스턴스) + 쿠폰(외부 발급)로 분리.

2.1 bongi_events (이벤트 마스터)

id · slug ('megacoffee5000') · title · subtitle
hero_image_url · hero_overlay (선착순 N잔)
coupon_name ('메가커피 아이스아메리카노') · coupon_provider ('giftshow'|'biztalk'|'manual')
coupon_value (5000원) · coupon_template_id
max_applications (5000) · current_count (auto)
start_at · end_at · is_active
agreement_texts JSONB [개인정보·제3자·마케팅]
cta_primary_label ('쿠폰 이벤트 참여하기')
cta_secondary_label · cta_secondary_url ('중고 보상 접수하기' → /buyback)
auth_method ('pass'|'sms'|'none') · age_minimum (14)
target_role_filter (NULL=공개) · created_by
alimtalk_template_id · alimtalk_variables JSONB
landing_template ('default'|'split'|'video') · brand_logo_url · partner_logo_url
metadata JSONB (UTM·캠페인·디자인 추가)

2.2 bongi_event_applications (신청자)

id · event_id (fk) · name · phone (마스킹 표시)
birthday · gender · ci (PASS 본인인증 토큰)
agreed_at · agreement_types JSONB (3종 동의 시각)
agreement_ip · agreement_user_agent

referrer · landing_page · created_at
customer_db_id (incentive_customer_db 연동)

id · event_id · serial · status ('available'|'issued'|'used'|'expired')

  • 중고 보상 접수 페이지로 자연스러운 redirect 유도

  • Hero 이미지 lazy + WebP

🔌 5. 외부 API 추상화

이벤트별로 다른 외부 서비스를 쓸 수 있도록 어댑터 패턴.

5.1 본인인증

제공자특징비용
KCB·NICE·KMC (PASS)정식 본인인증 · 만 14세 검증·휴대폰 명의·CI 발급건당 30~80원
SMS 인증 (Solapi·NHN Cloud)휴대폰 보유 검증만건당 8~12원
없음 (전화번호만)최소 마찰 · 봇 위험0원

이벤트별 auth_method 컬럼으로 선택. 어댑터: /server/services/auth-adapter.js

5.2 쿠폰 발급

제공자흐름비용
기프티콘몰·기프티콘 API실시간 발급 · 시리얼 즉시 반환정가
카카오 모바일 쿠폰 (Biztalk)알림톡 일체형정가
수동 (엑셀 사전 등록)bongi_event_coupons에 시리얼 임포트 후 순차 발급도매가

어댑터: /server/services/coupon-adapter.js · coupon_provider에 따라 분기

5.3 알림톡

  • 제공자: Solapi · NHN Cloud · KakaoBiz
  • 템플릿 ID + 변수 매핑 (이벤트마다 다른 메시지)
  • 버튼 — 쿠폰 사용 페이지 link, 매장 위치 link
  • 발송 실패 시 cron 재시도 (09:25 매일)

🔄 6. 신청 상태 전이

0. LP 진입 — utm tracking, 약관 모달 prefetch
1. 약관 3종 동의 — agreement_types JSONB 기록
2. 본인인증 — auth_method 따라 PASS·SMS·skip → CI/phone 확보
3. 신청 INSERT — bongi_event_applications row 생성 (queue_position)
4. 정원 검증 — current_count < max_applications면 쿠폰 발급, 아니면 대기/탈락
5. 쿠폰 발급 — coupon_provider API 호출 또는 풀에서 dequeue → coupon_serial 저장
6. 알림톡 발송 — 템플릿 + 변수 + 쿠폰 시리얼 → 카카오톡
7. 콜DB 자동 적재 — incentive_customer_db에 source='event:{slug}' 저장 → 상담사 배정 가능
8. 접수 처리 — 매장 매니저가 received=Y 토글 + 매장 배정
9. 결과 추적 — 쿠폰 사용·매장 방문·계약 전환까지 KPI
실패·재시도: 쿠폰 발급 실패 / 알림톡 실패 / 정원 초과 / 중복 신청은 모두 별도 status로 추적. 매일 cron 09:25 미발송 재시도.

🛡️ 10. 보안·법적 준수

  • PIPA (개인정보보호법): 약관 동의 IP·UA·시각 기록, 보존기간 명시, 마케팅 동의 별도
  • 만 14세 미만: PASS 검증 시 자동 차단, age_minimum 정책 명시
  • 중복 신청 방지: phone + event_id UNIQUE INDEX
  • 봇·어뷰징: hCaptcha (정원 대비 신청 폭주 시) + rate limit (IP당 분당 5회)
  • 쿠폰 시리얼 보안: 발급 시점만 노출, 알림톡 link 1회용
  • 마스킹: 어드민 list에서 이름 '홍길*' · 전화 '010-9999-****' (확장 권한자만 unmasked)
  • 감사 로그: 쿠폰 지급·접수 처리·매장 배정 모두 변경자·시각 기록

📖 11. 운영 매뉴얼 (어드민용)

  1. 신규 이벤트 생성: 어드민 → 이벤트 마스터 → [+ 신규] → 슬러그·제목·이미지·쿠폰사·약관 입력
  2. 이미지 업로드: Hero 이미지 (1080×1080 권장) · 파트너 로고 (SVG 권장)
  3. 쿠폰 풀 사전 등록 (수동형): CSV로 시리얼 N개 import (예: 5,000개)
  4. 약관 텍스트: agreement_texts JSONB 3종 (개인정보 수집·제3자·마케팅) 각 본문 입력
  5. 알림톡 템플릿: 사전 등록한 템플릿 ID 선택 + 변수 매핑
  6. 미리보기: 활성화 전 LP 미리보기로 데스크탑·모바일 확인
  7. 활성화 (is_active=true): 공개 URL 즉시 노출
  8. 신청자 모니터링: 실시간 카운트 + 시간대별 추이
  9. 접수 처리: 매장 배정 시 received=Y 자동, 콜DB → 상담사 자동 배분
  10. 종료 후 분석: 통계 대시보드에서 ROI · UTM · 전환 funnel
