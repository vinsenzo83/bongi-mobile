# 봉이 렌탈 상품등록 표준 양식 정의서

> 대상: 봉이 가전렌탈 상품을 봉이 DB(`rental_*`)에 등록하기 위한 **자체 표준 엑셀 양식**
> 작성일: 2026-05-22 · 상태: 초안 (승인 대기)
> 관련: `billigo-rental-system.md`(빌리고 import 파이프라인) · `billigo-rental-admin-ui.md`(어드민 UI)

---

## 0. 요약

봉이 가전렌탈 상품 등록의 **입력 경계를 봉이 자체 폼 하나로 고정**한다. 빌리고 원본 엑셀에 직접 의존하지 않고 — 빌리고든 다른 렌탈 중개사든, 어떤 소스가 와도 이 표준 양식으로 변환한 뒤 import 한다. 빌리고를 더 이상 쓰지 않게 돼도 영향이 없다.

표준 양식의 핵심 시트는 `등록확정_상세` 하나다. 모든 등록DB 파일은 이 시트명을 쓰고, **컬럼은 헤더명으로 자동 매핑**한다 — 정수기 그룹 24컬럼·가전 그룹 28컬럼이 한 파서로 처리된다.

---

## 1. 배경

### 1.1 왜 자체 폼인가
- 현재 import은 빌리고 원본 엑셀 2종(정수기 10시트·가전 24시트) 전용 파서에 묶여 있다.
- 빌리고 양식이 바뀌거나 빌리고를 안 쓰게 되면 파서를 다시 짜야 한다.
- → 입력 경계를 **봉이 표준 폼**으로 고정하면 외부 소스 변화가 격리된다.

### 1.2 등록DB 파일 난립 (해결 대상)
검수자가 만든 등록DB 파일이 날짜별로 구조가 제각각이었다:
| 파일 | 시트 구성 | 문제 |
|---|---|---|
| 정수기 (5/18) | 등록후보_정수기·등록확정_상세·공기청정기·비데 | 잡탕, 공청기·비데 중복 |
| 에어컨 (5/20) | README·수수료정책·등록확정_상세 | 28컬럼 |
| 공청기·비데 (5/21) | 등록후보/확정 ×2 | 24컬럼, 별도 |
| **정수기·공청기·비데 (5/22 최종)** | **등록확정_상세** 단일 | 24컬럼 — 정수기 그룹 통합본 |

→ 5/22 최종본이 정수기 그룹의 사실상 확정 양식. 본 정의서는 이를 표준화하고 가전 그룹까지 포함한다.

## 2. 양식 골격 — 시트 구성

| 시트 | 필수 | 역할 |
|---|---|---|
| **`등록확정_상세`** | ✅ 필수 | 모델 + 옵션 통합 데이터. 1행 = 1옵션 라인 |
| `README` | 선택 | 양식 가이드·기준월·작성 규칙 (참고용, import 무시) |
| `수수료정책` | 선택 | 렌탈사별 수수료율 (가전 그룹). 있으면 `rental_companies` 갱신 |

- `등록확정_상세`의 **1행은 헤더**, 2행부터 데이터.
- 헤더명으로 컬럼을 매핑하므로 컬럼 순서는 무관. 표준 사전에 없는 헤더는 무시.

## 3. 표준 컬럼 사전

`등록확정_상세` 시트가 가질 수 있는 전체 컬럼. **단위**: 모델(M) = 모델 단위 값, 옵션(O) = 옵션 라인 단위 값. **그룹**: 정수기·가전·공통.

### 3.1 모델 단위 컬럼 (M) — `rental_products`

| 표준 헤더 | 그룹 | 필수 | 형식 | DB 매핑 | 비고 |
|---|---|---|---|---|---|
| `노출순위` | 공통 | 선택 | 정수 | `display_rank` | 어드민 진열 순서. 비어도 됨 |
| `최종랭킹` | 가전 | 선택 | 정수 | `metadata.final_rank` | 셀렉 알고리즘 순위 (참고) |
| `시장성` / `시장성_⭐` | 공통 | 권장 | 정수 1~5 | `market_score` | 헤더명 둘 다 인식 |
| `브랜드` | 공통 | ✅ | 텍스트 | `brand` | 코웨이·삼성·LG… |
| `모델군` | 가전 | 선택 | 텍스트 | `metadata.model_group` | 시리즈 묶음 표시명 |
| `대분류` | 공통 | ✅ | 텍스트 | `category_id` (slug 매핑) | 정수기·공기청정기·비데·에어컨… → §6.1 |
| `중분류(상품명)` / `중분류` | 공통 | ✅ | 텍스트 | `name` (상품명 없을 때) | |
| `상품명` | 가전 | 선택 | 텍스트 | `name` (우선) | 풀네임. 있으면 name 으로 |
| `모델명` | 공통 | ✅ | 텍스트 | `model` | 모델코드 |
| `모델명_정규화` | 가전 | 선택 | 텍스트 | `model_key` | 다채널 매칭 키 |
| `시리즈키` | 가전 | 선택 | 텍스트 | `metadata.series_key` | 모델 그룹핑 키 → §5.2 |
| `상품URL` | 공통 | 선택 | URL | `product_url` | |
| `등록상태` | 공통 | 선택 | `O`/`X` | `registration_status` | `X` = 미노출 (`is_active=false`) |
| `평가메모` | 공통 | 선택 | 텍스트 | `evaluation_memo` | |

### 3.3 양식에 넣지 않는 값 (시스템 자동)
import 후 봉이가 계산·집계하므로 양식에 **넣지 않는다**:
- 집계: `option_count` · `months_available` · `care_services` · `monthly_fee_min/max` · `rebate_max`
- 인센티브: `point_weight`(P) · `margin` · `tier` · `is_premium` · `payback` — recalc RPC가 산출
- 자연키 보정: `variant_code` (충돌 시 import이 v1/v2 부여)

## 4. README · 수수료정책 시트

### 4.1 README (선택)
양식 작성 가이드·기준월·셀렉 기준 등을 적는다. import은 읽지 않는다(참고용).

### 4.2 수수료정책 (선택, 가전 그룹)
렌탈사별 수수료율 표. 헤더: `렌탈사 · 수수료 기준 · 수수료율 · 정액(원/건) · 비고`.
import 시 `rental_companies` 의 해당 렌탈사 `commission_rate`·`commission_method`·`commission_flat` 을 갱신한다. 없으면 신규 INSERT.

## 5. 작성 규칙

### 5.1 모델 단위 값은 모델 첫 행에만
한 모델이 여러 옵션 행을 가지므로, 모델 단위 컬럼(시장성·노출순위·시리즈키·상품URL 등)은 **그 모델의 첫 옵션 행에만** 채우고 나머지는 비운다. import은 빈 칸을 직전 모델 값으로 상속한다.

### 5.2 모델 그룹핑 키
연속된 옵션 행을 하나의 모델로 묶는 기준:
- `시리즈키` 가 있으면 → 시리즈키 단위로 1모델 (가전 — 색상만 다른 모델을 1상품으로)
- 없으면 → `(브랜드 + 모델명)` 단위로 1모델 (정수기)

### 5.3 빈 칸 처리
- 옵션 단위 컬럼이 비면 → `null` 로 적재 (해당 옵션에 그 값이 없음)
- 필수 컬럼(브랜드·대분류·모델명·약정기간·케어서비스·월납부액·리베이트)이 비면 → 그 행은 **오류 행**으로 리포트, 적재 보류

### 5.4 금액·숫자
- 금액은 원 단위 정수. 콤마·"원" 허용 (import이 제거).
- 약정기간·점검주기 등은 정수. "36M"·"36개월" 형태도 허용 (import이 숫자 추출).

## 6. 매핑 규칙 (import 동작)

### 6.1 대분류 → 카테고리 slug
`대분류` 텍스트를 `rental_categories.slug` 로 매핑. 미존재 카테고리는 오류 리포트(임의 생성 금지).
예: 정수기→`water-purifier` · 공기청정기→`air-purifier` · 비데→`bidet` · 에어컨→`aircon` · 냉장고→`refrigerator` …

### 6.2 렌탈사 → company
`렌탈사` 값을 `rental_companies.name` 으로 매핑 → `rental_products.company_id`.
- 정수기 그룹: `렌탈사` 컬럼이 없으면 `브랜드`(메이커명)를 회사로 사용.
- 가전 그룹: 같은 모델이 여러 렌탈사로 오면 **렌탈사별 별도 `rental_products` 행** (현 스키마 — company가 product에 속함).
- `수수료율(%)`·`수수료 기준` 이 있으면 해당 company 의 commission 갱신.

### 6.3 케어서비스 정규화
`rental_product_options.care_service` 는 DB CHECK 제약상 `방문`·`셀프`·`null` 만 허용.
양식의 원본 값("미포함"·"설치"·"12개월 (프리미엄)"·"기사 설치" 등 가전 케어 텍스트)은:
- `방문`/`셀프`로 정규화해 `care_service` 에 — 관리·점검·방문 키워드 → `방문`, 자가·셀프·미포함 → `셀프`
- 원본 텍스트는 `variant_label` 또는 `metadata.care_raw` 에 보존

### 6.4 자연키·중복
옵션 자연키 7-tuple `(company, model, months, care_service, inspection_cycle, ownership_months, variant_code)`. 같은 키 행이 값까지 동일하면 1개로 dedup, 값이 다르면 `variant_code` 에 v1/v2 부여해 모두 보존(빌리고 파서와 동일 — 행 누락 0).

### 6.5 봉이 인센티브 컬럼 보존
import은 `rental_products`/`rental_product_options` 의 `point_weight`·`tier`·`margin`·`is_premium`·`payback`·`ticket_*` 을 **절대 덮어쓰지 않는다**. 빌리고 필드만 갱신.

## 7. import 파이프라인

- 신규 endpoint 또는 기존 `POST /api/rental/import` 에 `file_type='등록폼'` 분기 추가.
- 파서 `server/services/rental-register-parser.js` (신설) — `등록확정_상세` 헤더를 §3 표준 사전으로 매핑.
- preview(미리보기 diff) → commit(async UPSERT) — 기존 빌리고 import과 동일 흐름.
- 헤더에 표준 사전 외 컬럼이 있으면 warnings 에 기록(무시).
- 필수 컬럼 누락 행은 오류 리포트.
